# Inverse Navier-Stokes Solver for Vortex Clusters



This project looks at a simplified inverse problem for the 2D Navier-Stokes equations. The goal is to take a vorticity field after it has evolved for some fixed amount of time and try to recover the initial vortex configuration that produced it.



I restrict the problem to a structured family of flows generated by small clusters of two or three vortices. The four classes used here are same sign pairs, opposite sign pairs, same sign triples, and mixed sign triples.



The basic pipeline works in two stages. First, a convolutional neural network classifies the evolved vorticity field according to which of the four vortex families it came from. The result is then passed to a separate inverse model trained for that family.



Rather than having the inverse models predict the full initial 128 x 128 vorticity field directly, they predict the parameters of the original vortices, namely their positions, amplitudes, and widths. These parameters are then used to reconstruct the initial field.



The training data are generated numerically. Initial vortex clusters are constructed on a periodic domain and evolved with a Fourier Navier-Stokes solver using RK4 time stepping. The data generation notebook contains the full procedure, so the large generated datasets themselves are not included here, as some of them are \~6 GB in size.



The classifier reaches about 99.9% accuracy on held-out data. In the full pipeline test, it misclassified 3 out of 4000 examples. Mean relative L2 reconstruction errors were about 3% for opposite sign pairs, 7% for same sign pairs, 11% for same sign triples, and 13% for mixed sign triples.



The notebooks are organized in the following order:



01\_cluster\_data\_generation.ipynb
Generates the initial vortex configurations and evolves them forward under Navier-Stokes.



02\_train\_pattern\_classifier.ipynb
Trains the classifier used to identify the vortex family from the evolved field.



03\_train\_inverse\_models.ipynb
Trains the four family-specific inverse models.



04\_results\_pipeline.ipynb
Combines the classifier and inverse models and evaluates the full pipeline, including reconstruction errors and some of the main failure cases.



This is meant as a small test problem for using machine learning on an inverse PDE problem, rather than an attempt at solving the general inverse Navier-Stokes problem. In particular, I wanted to test a pipeline where the machine-learning model makes use of the low-dimensional structure of the underlying physical problem rather than treating the fields as completely generic images.
